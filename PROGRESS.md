## What exists today
- `index.html` — homepage (white + LinkedIn-blue theme).
- `products.html` — top-level catalog page: 9 categories shown as bigmint.co-style rectangular tiles (`.cat-showcase`/`.cat-tile`) — hero image, hover reveals a subcategory-link overlay, dark bottom bar links to the category page.
- `products/<category-slug>/index.html` — one per category (9 total): subcategory icon grid, PLUS a "Shop All" section below it (sidebar-filterable flat listing of every product in the category — see conventions below).
- `products/<category-slug>/<subcategory-slug>/index.html` — one per subcategory (51 total): leaf-node grid + a "Search what's in your mind" search bar.
- `products/<category-slug>/<subcategory-slug>/<leaf-slug>/index.html` — one per leaf node (212 total): Snappy-style browse layout — top "Filters/Reset" bar + budget tabs, left sidebar with a checkbox per **occasion** (Employee Onboarding, Festivals, Corporate Events, etc. — 8 total, shared with the mega-menu's `OCCASIONS` list). A leaf page only ever shows that leaf's own 4 products (Pens page never shows Pencils) — occasion checkboxes just narrow which of those 4 match a use case (OR within the facet, AND with the price tabs).
- `products/<category-slug>/<subcategory-slug>/<leaf-slug>/product-details.html` — one generic template per leaf, reads `?id=&slug=` from the URL and fetches `data.json` in the same folder to render a Snappy-style PDP (image gallery of 4 + swappable thumbnails, price, description, specs, Enquire Now CTA).
- `products/.../<leaf-slug>/data.json` — 4 placeholder products per leaf, each with a generated brand-style name (e.g. "Marlow Premium Pens"), a one-line tagline, price, 4 picsum images, a description (leads with the tagline), and specs (Category/Material/Customization/MOQ/Lead Time). All data is dummy/placeholder — no real backend yet.
- Nav mega-menu on "Products" (desktop hover only; mobile keeps a plain link) — two columns: **Shop by Occasion** (8 items, all currently point to `products.html` — no dedicated occasion pages yet) and **Shop by Category** (9 real category links) + an "Explore All Products" CTA.
- `assets/img/brand-icon.png` — the "K" mark cropped from the user-supplied brand lockup (see brand refresh entry below); all pages reference it via `/kaleido_website/assets/img/brand-icon.png`.
- `scripts/generate_products.py` — the generator for the entire `/products/` tree. **This is the source of truth for the taxonomy.** To add/edit/remove categories, subcategories or leaf items, edit the `TAXONOMY` dict at the top of this script and re-run `python3 scripts/generate_products.py` — it wipes and rebuilds `products/<category>/` for every category on each run.

## Key conventions (don't relitigate these)
- **URL prefix**: every internal link on generated pages uses the absolute path prefix `/kaleido_website/...` (not relative `../../..`), since the site is a GitHub Pages *project* site living at that subpath. This was a deliberate choice to avoid relative-path bugs across 4 levels of nesting.
- **Slugs**: category slugs are hand-picked in `TAXONOMY` (e.g. `stationary-and-office-supplies` — intentionally matches the user's own URL example spelling, not the correct "stationery"; `gifting` for Corporate Gifting; `it-and-electronics`). Subcategory and leaf slugs are auto-generated via `slugify()` (lowercases, `&`→`and`, non-alphanumerics→`-`).
- **Design system reuse**: new components added to `assets/css/styles.css` (search near the bottom, "SECTION 11" onward): `.has-mega`/`.mega-menu` (nav dropdown), `.corp-grid`/`.corp-card` (corpattire-style small-icon category grid, used at every taxonomy level), `.search-bar`, `.breadcrumb`, `.price-tabs`, `.item-grid`/`.item-card` (leaf-page product grid), `.pdp-*` (product detail page).
- **Reveal-on-scroll gotcha**: `main.js`'s IntersectionObserver only scans `.reveal`/`.reveal-stag` elements present at page load. Any content injected later via JS (like the PDP gallery) must NOT use those classes, or it stays permanently invisible — already hit and fixed once in `product-details.html`'s generator function.
- **Span-vs-div-inside-`<a>` gotcha**: `.item-card`'s image/name/price wrapper elements must be `<div>`, not `<span>`. A plain block container (`.item-card{ display:block }`) does NOT blockify inline children the way a flex/grid container does (that's why `.corp-card`'s `<span>`-based icon+label worked fine — it's `display:flex`). With `<span>`, `aspect-ratio` on `.item-img` was ignored and the name/price text overflowed past the computed box and got clipped by the card's `overflow:hidden`, so nothing but the image showed. Already hit and fixed once — if a new card-style component is added on a plain-block container, use `<div>` for its structural wrappers.
- **Strategic Sourcing** is flagged `is_service=True` in the taxonomy — it's framed as a procurement capability rather than a fixed catalogue (different eyebrow/intro copy), but reuses the same page template as the other 8 categories for consistency.
- **Catalog page density fix**: category/subcategory/leaf hero sections used to be two stacked `.section-inner` blocks (each with ~56–120px top+bottom padding), leaving a huge dead gap between the heading and the grid below, plus the `.section-head` text was capped at 640px inside a 1320px-wide container leaving a large blank strip on the right on wide screens. Fixed via `.catalog-top`/`.catalog-bottom` padding overrides (SECTION 18 in `styles.css`) and a `.catalog-hero-grid`/`.catalog-hero-media` two-column hero (SECTION 18) that puts a themed picsum image on the right instead of empty space, on all three of `build_category_page`/`build_subcategory_page`/`build_leaf_page` in `generate_products.py`.
- **Breadcrumb sibling dropdowns** (SECTION 19 in `styles.css`, `breadcrumb()` in the generator): every non-current breadcrumb crumb now shows a hover dropdown of its siblings (e.g. on the Pens page, hovering "Writing & Paper" lists Pencils/Notebooks/etc.; hovering "Stationery & Office Supplies" lists sibling subcategories; hovering "All Categories" lists all 9 categories). Lets a visitor jump sideways without backtracking through each intermediate listing page. `breadcrumb(items)` now accepts an optional 3rd tuple element per crumb: a `[(label, href), ...]` sibling list.
- **Category-page "Shop All" bypass** (SECTION 20 in `styles.css`, in `build_category_page()`): the user found products.html → category → subcategory → leaf → product-details too many clicks, but wants every existing page kept (SEO + internal linking value), so nothing was deleted or restructured. Instead each of the 9 category pages now has a second section below the subcategory icon grid: a Uline/Grainger-style flat, faceted listing of *every* product in that category (aggregated across all its subcategories/leaves via `gen_products()`), with a left sidebar to filter by subcategory and price (client-side JS, AND logic, mirrors the existing `.price-tabs` pattern). Clicking a product card goes straight to that product's existing `product-details.html` — so category → product is now 1 click instead of 3, while the subcategory/leaf pages remain fully live and linked (from the icon grid, mega-menu, and breadcrumbs) for anyone who wants to browse hierarchically or land on them from search. Only added to the category level — subcategory/leaf pages were intentionally left alone.
- **Ratio-based IntersectionObserver reveal gotcha (new)**: `main.js`'s scroll-reveal uses `threshold: 0.15`, i.e. 15% of the *target element's own height* must be simultaneously visible in the viewport. A tall grid (e.g. the 116-product Shop All grid, ~11,000px tall) can never reach 15% visible no matter how far you scroll, since even a full viewport of visible height is a tiny fraction of the element's total height — so `.in` never gets added and the content stays permanently at `opacity:0`. Fix: don't put `.reveal`/`.reveal-stag` on any container whose full height will regularly exceed roughly 5–6x the viewport height; the Shop All grid intentionally has no reveal animation for this reason. This is a different failure mode from the earlier "reveal-on-scroll gotcha" (that one was about timing/late DOM injection) — this one is about element size vs. viewport size.
- **Leaf-page browse layout (Snappy `browse-gifts`-style)** (SECTION 21 in `styles.css`, in `build_leaf_page()`): the user showed Snappy's Browse Gift Catalog page (top "Filters / Reset" bar + budget tabs, left "Categories" checkbox sidebar) and asked for that look on leaf pages. First pass made the sidebar checkboxes pull in *sibling leaves'* products (e.g. checking "Pencils" on the Pens page) — user explicitly rejected this ("pens should only contain pens, not pencils"). Reworked to facet by **occasion** instead: `gen_products()` now tags each product with 2–3 deterministic entries from `OCCASIONS` (`["Employee Onboarding","Work Anniversaries","Festivals","Birthdays","Corporate Events","Conferences","Product Launches","Rewards & Recognition"]` — the same 8 used in the mega-menu's "Shop by Occasion" column, now a single shared list so they can't drift). Each leaf page's grid is only ever that leaf's own 4 products (`data-occasions="<slugs>"`); checking sidebar boxes narrows by occasion (OR within the facet) AND'd with the price tabs. "Reset" unchecks everything and clears price back to All.
- Also widened the gap between the hero and the content below it slightly (`.catalog-top` bottom padding 26px→36px, `.catalog-bottom` top padding 0→10px) — the very first density fix made it too tight edge-to-edge.
- **Brand refresh (strict palette + font)**: user supplied an official brand kit (logo lockup + palette LinkedIn Navy #0A66C2 / Bright Blue #2684FF / Light Blue #A7D3FF / Pale Blue #EAF3FF + Montserrat typography). `--brass` already equalled the new Navy exactly; updated `--brass-soft`→#2684FF, `--beige`/`--cream-warm`→#EAF3FF, `--beige-deep`/`--teal`/`--peach-tint`→#A7D3FF (`:root` in `styles.css`) so the change is one place, cascades everywhere. Swapped every Google Fonts `<link>` (FONT_LINKS in the generator, plus the hardcoded ones in `index.html`/`products.html`) from Roboto/Roboto Condensed to Montserrat, and `--sans`/`--serif-display`/`--label` all now point at Montserrat. `assets/img/brand-icon.png` was re-cropped from the user's pasted lockup JPG (Pillow, row/column non-white-pixel band detection to isolate just the "K" mark from the wordmark+tagline below it) — copy/tagline text elsewhere on the site was deliberately left unchanged, only logo/colour/font were in scope.
- **Reveal-on-load gotcha (new)**: elements already inside the viewport at page load were staying invisible until the user scrolled, because `IntersectionObserver`'s first callback can lag one frame behind first paint. Fixed in `main.js`: before calling `io.observe(el)` for each `.reveal`/`.reveal-stag` element, synchronously check `getBoundingClientRect()` — if it's already on-screen, add `.in` immediately instead of waiting on the observer. Elements below the fold still animate in on scroll as before.
- **products.html hero density**: this page is hand-authored (not generated by the script), so it hadn't gotten the `.catalog-top`/`.catalog-bottom` tightening applied to the generated pages — same fix applied here directly.
- Verification method: no persistent browser available by default — use `python3 -m http.server` from `/Users/nemo/Desktop` (one level above the repo) so root-relative `/kaleido_website/...` paths resolve exactly like production, then `curl -o /dev/null -w "%{http_code}"` per file. Chrome browser tools (`mcp__claude-in-chrome__*`) were available and used for real visual verification in the session that built this — use them again if available.

- Mobile nav does not expose the mega-menu categories (by design, kept simple) — mobile users can still reach `products.html` via the flat "Products" link.
